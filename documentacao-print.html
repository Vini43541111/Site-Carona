CaronaUni Documentação Técnica v2.0 1. Descrição do Sistema
Seção 1
Descrição do Sistema

O CaronaUni é uma plataforma web de caronas universitárias desenvolvida para conectar, de forma simples e segura, estudantes da Unoesc (Universidade do Oeste de Santa Catarina) que oferecem vagas em seus veículos com estudantes que precisam de deslocamento até o campus.

A plataforma resolve problemas recorrentes na comunidade acadêmica: a dificuldade de encontrar caronas confiáveis, a ausência de um processo organizado para solicitar e confirmar vagas, e a falta de histórico e avaliação para aumentar a confiança entre os usuários.

O sistema é desenvolvido como um protótipo funcional de alta fidelidade em HTML, CSS e JavaScript puro, com mapa interativo via Leaflet.js + OpenStreetMap, hospedado no GitHub Pages para acesso público sem necessidade de infraestrutura de servidor.

🎯 Propósito
  • Facilitar o deslocamento diário da comunidade acadêmica
  • Reduzir custos individuais de transporte
  • Diminuir o número de veículos em circulação
  • Promover sustentabilidade no campus
  • Aumentar a confiança entre usuários via avaliações
⚙️ Fluxo Principal
  1. Usuário faz login via SSO Unoesc (mock)
  2. Motorista cria carona com rota e horário
  3. Passageiro busca e solicita uma vaga
  4. Motorista aceita ou recusa a solicitação
  5. Carona é realizada e ambos se avaliam
  6. Reputação de ambos é atualizada

Público-alvo

Estudantes regularmente matriculados na Unoesc — tanto motoristas que desejam compartilhar viagens e reduzir seus custos, quanto passageiros que buscam deslocamento confiável até o campus. O acesso é exclusivo a membros da comunidade acadêmica, garantido via autenticação institucional.

Contexto do projeto: Esta é uma entrega evolutiva do semestre 2026/1, dando continuidade ao levantamento e modelagem realizados no semestre anterior. O foco desta fase é o protótipo funcional navegável, o modelo ER e a documentação técnica consolidada.

CaronaUni Documentação Técnica v2.0 4. Arquitetura do Sistema
Seção 4
Arquitetura do Sistema

O sistema segue uma arquitetura em três camadas com separação clara de responsabilidades entre Interface Web, Backend e Banco de Dados. No protótipo atual, apenas a camada de Interface está implementada; as demais são modeladas para a fase de desenvolvimento real.

🌐 Frontend — Interface Web

Protótipo em HTML5, CSS3 e JavaScript puro. Responsivo e totalmente navegável. Mapa interativo via Leaflet.js com tiles OpenStreetMap. Geocodificação reversa via Nominatim API.

HTML / CSS / JS Leaflet.js OpenStreetMap
⚙️ Backend — API REST

Camada de serviços responsável pela lógica de negócio: autenticação via JWT, gerenciamento de caronas, controle de solicitações, avaliações e mensagens entre usuários.

Node.js / Python REST API JWT Auth
🗄 Banco de Dados

Armazenamento relacional das entidades principais do domínio: Usuário, Carona, Solicitação, Avaliação e Mensagem, com integridade referencial via chaves estrangeiras.

PostgreSQL / MySQL Modelo Relacional
🔐 SSO Institucional

Integração com o sistema de autenticação da Unoesc para validação de matrícula ativa. No protótipo atual, o SSO é simulado — qualquer credencial @unoesc.edu.br é aceita.

OAuth 2.0 / SAML Mock no protótipo

Fluxo de Dados

Requisições comuns:
Interface Web → HTTPS → API REST → Serviços (Carona / Usuário / Mensagem) → Banco de Dados

Autenticação:
Interface Web → SSO Unoesc → Token JWT → API REST (header Authorization)

Tecnologias Utilizadas no Protótipo

Seção 5
Protótipo Navegável

O protótipo foi desenvolvido em HTML/CSS/JavaScript puro, sem dependências de build ou bundler. Está hospedado no GitHub Pages e pode ser acessado publicamente pelo link abaixo, sem necessidade de instalação ou conta.

🔗 Link do Protótipo:
https://viniciusoliveira-ai.github.io/Site-Carona/

Telas Implementadas

🔐 Login
Autenticação via SSO Unoesc + formulário manual com e-mail e senha institucional
🏠 Dashboard
Estatísticas pessoais, notificações recentes, próximas caronas e atalhos rápidos
🔍 Buscar Carona
Mapa interativo, lista de caronas disponíveis com filtros por horário e distância
➕ Oferecer Carona
Criação com mapa (clique = origem, duplo clique = destino), vagas e recorrência
📍 Detalhes
Informações da carona, perfil e avaliações do motorista, mapa de rota
📋 Solicitações
Gerenciamento das solicitações recebidas pelo motorista: aceitar ou recusar
⭐ Avaliação
Sistema de estrelas com critérios detalhados, tags rápidas e comentário
📜 Histórico
Registro de caronas passadas, futuras e pendentes de avaliação, com abas
👤 Perfil
Dados pessoais, veículos cadastrados, reputação detalhada e preferências
Critério de pronto atendido: Fluxo ponta a ponta funcionando — login → buscar carona → solicitar vaga → aceitar solicitação → avaliar usuário. Mapa navegável com definição de origem e destino por clique. Protótipo hospedado e acessível via link público.

Fluxo de Navegação Principal

O usuário inicia em index.html (Login) → é redirecionado para dashboard.html → pode buscar em buscar.html, ver detalhes em detalhes.html e solicitar uma vaga. O motorista gerencia solicitações em solicitacoes.html. Após a carona, o passageiro avalia em avaliacao.html. Todo o histórico fica em historico.html e o perfil em perfil.html.

CaronaUni Documentação Técnica v2.0 8. Plano de Execução
Seção 8
Plano de Execução

O projeto segue um modelo ágil incremental, dividido em iterações com entregas parciais e funcionais. As iterações 1 a 5 já foram concluídas nesta fase. A iteração 6 (Backend) está planejada para o próximo semestre.

Iteração 1 — Levantamento e Modelagem
Revisão dos requisitos do semestre anterior. Atualização dos diagramas de caso de uso, classes, sequência e atividades. Definição do escopo da entrega evolutiva.
Iteração 2 — Protótipo: Login + Dashboard + Buscar
Desenvolvimento das telas de login, dashboard principal e busca de caronas com mapa interativo Leaflet.js + OpenStreetMap e geocodificação via Nominatim.
Iteração 3 — Protótipo: Criar + Solicitar + Aceitar
Tela de criação de carona com mapa interativo (clique para origem e destino), fluxo de solicitação de vaga pelo passageiro e gerenciamento de solicitações pelo motorista.
Iteração 4 — Protótipo: Avaliação + Histórico + Perfil
Tela de avaliação pós-carona com critérios detalhados e tags rápidas, histórico de caronas com abas e filtros, e tela de perfil com preferências e veículos.
Iteração 5 — Modelo ER e Documentação Técnica
Elaboração do modelo entidade-relacionamento compatível com o fluxo principal do sistema, documentação técnica evolutiva consolidada e publicação do protótipo via GitHub Pages.
Próximo — Iteração 6: Backend (API REST + Banco de Dados)
Implementação real da API com Node.js ou Python (FastAPI/Django), banco de dados PostgreSQL, autenticação JWT e integração com SSO da Unoesc. Substituição dos dados mockados por chamadas reais à API.
